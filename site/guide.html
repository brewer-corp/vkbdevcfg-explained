#What this program is

VKBDevCfg is the Windows program that configures VKB joysticks, throttles and grips. It is the thing that decides which physical button becomes which button in your flight sim, what colour an LED is, how an axis behaves, and what a thumb button does when you hold a shift key.

It is also the tool that flashes firmware onto the stick, and the tool that calibrates its axes.

It does three jobs

Configure the stick · flash firmware · run self-tests and calibration.

It has two halves

A small toolbar across the top, and a large tabbed work area underneath.

It only talks to one stick at a time

You pick a device at the top, then everything below applies to that device.

Source

This is a companion to the DCS Tutorial video. That video is the basis for everything in the reference sections; this page reorganises it into something you can skim, fixes the ordering, and adds the mental model that the video describes but never names.

Extract the firmware pack into its own folder rather than dumping it with everything else. It is ~66 files split by generation and model, and you will want to navigate straight to your stick. Naming is consistent: __BlackMamba_v2_20_C.vkb, __KingCobra_v2_20_C.vkb, and so on.

#Unlocking the full UI

By default VKBDevCfg hides a substantial amount of its own interface. The video's first real task is to turn the extra parts on. This is done by editing a text config file the program creates itself.

The procedure

  1. Open VKBDevCfg once, then close it. On first run it writes a file called zconfig.ini into its own folder. If you never see that file appear, you did not actually launch it.
  2. Open zconfig.ini in any plain text editor. Not Notepad-save-as-CSV, and keep it as plain text.
  3. Find the [user] section and add a line under it.
  4. Find partial_wr and change its value to 1.
  5. Find partial_calibration and change its value to 1.
  6. Find the [common] section and add two lines under it.
  7. Save, and restart VKBDevCfg.

I confirmed by disassembling the current build that the lower-case underscore forms from the video do not appear in the executable. Use the manual's spelling.

#Firmware updates

Firmware is the code running on the stick's microcontroller. Updating it is optional for a brand new device and increasingly important for an older one — it is how you get bug fixes and new features.

Via ZBootloader

  1. Run ZBootloader2.
  2. It lists every VKB device it can see. Double-click yours.
  3. Point it at the .vkb file for your exact model, in the folder you extracted the firmware pack into.
  4. Confirm it shows the version you expect — the version number is printed next to the file.
  5. Click Flash. It takes roughly 30 seconds, then closes itself.
From inside VKBDevCfg

You do not have to run ZBootloader separately. Tools → Bootloader in VKBDevCfg launches it. The video notes this is mostly for recovery situations.

VKBDevCfg shows the firmware version currently on your stick next to the device name in the blue bar at the top, so you can check whether an update is warranted before you flash anything.

Match the model, not the family

The firmware pack contains separate images per model and per hardware generation (1stGen/, …). Flashing the wrong image is the single most destructive thing you can do with this toolchain. Check the filename against the model printed in VKBDevCfg's device list.

#The mental model

This is the part the video describes accurately but never summarises, and it is the reason the tool feels confusing. There are three different kinds of “button” and “axis” in play, and the program makes you configure each layer separately.

Layer 1

Physical

The raw hardware. “The switch soldered to pin 10 on my grip.” Numbered from the manufacturer. You see these in Buttons → Physical Layer and Axes → Physical Axis.

→
Layer 2

Logical

The numbering Windows actually sees. “Button 37 in DirectInput.” Each physical input can be mapped to any logical button you like — or to several at once.

→
Layer 3

What it does

What the game receives: a button press, a hat-switch direction, a keystroke, a macro, a multimedia key, a system action.

Why you have to care

The same indirection exists for axes. Physical axes are the raw sensor values straight off the gimbal. Logical axes are what Windows reports — the two are connected by a table you fill in.

In practice, on a default-configured VKB stick the physical axis is the logical axis, one for one. The video says as much: if your X axis happens to be physical axis 1, you set logical axis 1's source to physical axis 1. Leave it alone unless something is wrong.

The most common misunderstanding

People look for “where do I set button 5” and find nothing, because button 5 might be a logical button while the thing they pressed is physical button 12. Always ask which layer you are in before changing a number.

The shifter example

The video walks through a shifter, and it is the clearest illustration of why virtual buttons exist:

  1. Your trigger is physical button 10. By default that drives logical button 10.
  2. You want trigger alone → logical button 79, and trigger + shift → logical button 80.
  3. One physical input cannot produce two logical outputs at once — so the shift condition is handled by changing what physical button 10 is while shift is held.
  4. Logical button 79 gets a real physical source (your trigger). Logical button 80 has no physical switch left to drive it, so it is assigned to a virtual button — a button that does not physically exist and is only ever triggered by the firmware.

That is the whole trick: virtual buttons let one physical input fan out into several logical buttons under different conditions.

#How it actually works

The mental model above is the video's. Here is what VKB's own manual reveals, which is more precise and a little more alarming. Sourced from the official NJoy32 Configuration Utility User Guide v2.19 (August 2023, 163 pages) linked from their downloads page.

The thing that changes everything

The stick is a real-time signal processor, not a remapping table. Almost every “logical” feature — shift hierarchies, relative axes, curve equalisation, macro timing, LED priority — is executed in firmware on the device, not in the PC program. Your PC tool does exactly two things: push a parameter block into the stick, and pull it back out.

This is why the tool can be a plain grid of cells with no performance concerns, and also why you cannot reproduce its behaviour with a software remapper on the host. That work happens at the USB polling rate, in hardware.

The real currency is “lines”

Not buttons. The manual is explicit that “button” is shorthand — a hat switch is four lines, a two-position toggle is two lines, an encoder is two:

“Every pair of button contacts is represented as single line. So simple button occupies one line, toggle switch On–Off–On — two lines, 4-way HAT — 4. Njoy32 controller can process up to 128 lines.”

Lines are numbered by wiring, and grouped eight to a register — Reg#1 … Reg#16. That is why the physical grid is 128 cells and why nothing in the tool makes sense unless you think in those numbers.

It is a four-layer pipeline, not a two-layer map

Layer 1

Physical line

Wired contact or sensor. Numbers 1–128, fixed by hardware.

→
Layer 2

Physical function

What the line is: Button, ButAlt, Shift, SubShift, Toggle, Encoder, POV, Tempo, Generator… 26 types.

→
Layer 3

Logical line

What Windows sees. Defaults to the same number if you do nothing.

→
Layer 4

Logical function

What the game receives: press, HAT, keystroke, mouse, macro, media, system. 11 types.

The video collapses layers 2 and 3 into one step. Separating them is what makes the tool feel arbitrary: some physical functions have no logical function at all — Shift is one. It is a modifier, not an output.

Three more things the video never mentions

  • En vs Vs — every line has two separate visibility gates. One says the line exists, the other says it is currently live. They are not the same and conflating them is the most common misconfiguration in the whole tool.
  • Virtual controllers 1–8 — a workaround for Windows' hard limit of 8 axes per HID device. With more than 8 axes you must spread them across virtual controllers, and the tool makes you do it manually.
  • Only one live configuration exists on the device. There is no multi-slot store; Get retrieves the entire parameter set in one go, whatever tab you happen to be on. Your per-game profiles live in .cfg files on the PC, not on the stick.
Occupancy

Logical line numbers must be unique. The manual is blunt: “This number must NOT be the same with existing physical button line.” The tool gives you no visual warning when you collide two assignments — one of the clearest opportunities for a better interface.

#Anatomy of the window

Once you have picked your device, the window splits into two very different regions, and the video is clear that people routinely conflate them.

Top — the toolbar

Device selection, plus three tabs: Action, Tools, Settings. This is what you use constantly.

Bottom — the work area

Five tabs: Test, Global, Profile, Macro. This is where the actual configuration lives.

Pick your device first

At the very top is a blue box listing every connected VKB device. Click yours. The app takes a second or two to read it, and then shows its firmware version. Everything below is scoped to the device you picked. If you have a stick and a throttle plugged in, you must switch between them.

#Get / Set / Save / Load

These four buttons cause more confusion than anything else in the program, so they are worth stating plainly.

ButtonWhat it doesWhen you use it
Set Writes the settings currently shown in the software into the physical stick. After every change you want to keep. Changes in the UI are otherwise just a draft.
Get Reads the settings out of the stick back into the software. When what you see disagrees with what the stick is doing — e.g. after plugging in a stick configured on another machine.
Save Saves the current configuration to a file of your choosing. To keep a separate setup per game.
Load Loads a previously saved configuration file into the software. To switch between those per-game setups.
The single most common mistake

Changing a setting in the UI does nothing to the stick until you press Set. You will change an LED to purple, look down at your joystick, and see it still yellow — and conclude the software is broken. It is not; you just have not written the change down.

Per-game profiles

The Save/Load pair exists to solve a real problem: DCS, Microsoft Flight Simulator and Elite Dangerous all want different bindings. The workflow is:

  1. Configure everything for DCS. Save → name it DCS.cfg.
  2. Reconfigure for Elite Dangerous. Save → Elite.cfg.
  3. Before playing, Load the right file, then press Set to push it into the stick.
Tip

Turn on Settings → Set After Load and the Set becomes automatic — loading a file immediately writes it to the stick. One less step, and one less way to be confused.

How calibration actually works

  1. Click Start Calibration.
  2. A dialog appears listing the axes. Select the ones you want (with partial_calibration=1 in zconfig.ini you get to choose; without it, it assumes you want all of them).
  3. Click Set.
  4. Move every selected axis to its extreme position — full forward, full back, full left, full right, throttle to the stops.
  5. Click End Calibration. Done.

If you mess it up midway, Cancel Calibration gets you out without writing bad values.

Settings

Four checkboxes and a skin picker. These change how the program behaves, not how your stick behaves.

OptionOnOff
Auto Read Parameters When you plug a stick in, it automatically reads and displays its settings. You must press Get manually every time you connect.
Set After Load Loading a config file immediately writes it to the stick. Loading only fills the UI; you still press Set.
Partial Write Pressing Set asks which categories to send (LEDs, buttons, axes…). Everything is sent every time. Simpler, and safer if you are not sure.
Partial Calibration Calibration lets you pick which axes to calibrate. Calibration always covers every axis.

Skin just changes how the program looks. The video's author prefers the dark “Metro” skin over the default white one; purely cosmetic.

#Test tab

For verifying hardware. It is read-mostly, so it is the safest place to poke around, and the first place to look when something seems broken.

Info

Plain device facts: model name, version, firmware version. Nothing to configure. The video's verdict: “pretty straightforward”. Correct — use it to confirm you are editing the right device and running the firmware you think you are.

Buttons / POVs

Press a button on the stick and watch which cell lights up. This is the tool that tells you which physical button number a given switch is wired to.

This is the most useful screen in the program

Before you remap anything, find out the physical number. Press the button, read the number, then go and change that one.

Axes

Live axis readout — move the stick and watch the values move. Use it to confirm an axis is alive and to see its resting centre before and after calibration.

External Devices

Lists other VKB devices currently plugged in. Useful on multi-stick setups.

Miscellaneous — the LED tester

Requires test_misc_enabled=1 in zconfig.ini.

  1. Type an LED number into the box — e.g. LED 0 or LED 10.
  2. Hold the button next to it. That LED flashes on the physical stick.
  3. Set a colour in the panel on the right and click OK to change what colour the test uses.
LED numbering is per-device

Different sticks have different LEDs. The video's example — a Gladiator NXT with LED 0, LED 10, LED 11 — does not transfer to another model. Check your own device.

Restart afterwards

The manual instructs you to restart the joystick after testing LEDs. The video's author cannot explain why — but the manual is explicit, so do it.

#Global tab

Settings that apply to the whole device rather than to one axis or button.

Common

  • Button count — how many buttons the device exposes to Windows.
  • POV / hat count — how many hat switches. Setting this to zero makes the hats disappear from Windows entirely.
  • Timing — debounce and timing behaviour per button.
  • Keyboard — enables a virtual keyboard, so a stick button can emit a keystroke. Choose classic or modified.
  • Mouse — the same idea for a virtual mouse.
Advice from the source

“I'd recommend leaving most of these defaults.” Agreed — these are easy to break and hard to diagnose.

External

Low-level microcontroller configuration — SPI, serial, GPIO and the like.

Leave this alone

The video's author is blunt: “I'm going to be honest, I don't know that much about microcontrollers… unless you really know what you're doing you probably shouldn't mess with this tab.” Firmware-level settings that can stop a stick responding.

LEDs

Where you will spend real time if you care about lighting.

How it works

LEDs are configured as a list of events. An event is the thing that causes the light to change. For each event you choose which LED, which colour, and which mode.

EventMeaningExample
Event 0The default / idle state. Lights are on unless something else overrides them.LED 10 constant purple at rest.
Logical ButtonLight changes when a particular logical button is pressed.Press logical button 10 → LED 10 turns yellow.
Axis, Hat, etc.Light reacts to an axis crossing a threshold, a hat direction, and so on.LED 7 turns green when the throttle is past 80%.
You cannot make an LED a colour it is not

Not every stick has RGB LEDs. If your stick's LED 0 is a single fixed-colour LED, selecting green in the dropdown will simply have no effect. The video demonstrates this — the Gladiator NXT has one RGB LED and the rest are single-colour.

#Profile tab

This is where you will spend most of your time. Axes, buttons, POVs and logical functions all live here.

Axes — physical

Configuration of the raw axis signals, before they become logical axes.

SettingEffect
Sensor typeHow the sensor is read. Leave at default — the video warns that changing it will break the axis.
Virtual trimmerEnables a software trimmer for the axis.
Auto calibrationWhether the axis self-calibrates.
InvertFlips the axis direction.
Bias, %Shifts the centre point. The main fine-tuning control for “my axis is centred 2% off”.
Low / High limitsClamps the usable travel at each end.
Dynamic filteringSmoothing applied to the signal.
The most common fix

“My axis is slightly off-centre” is a bias problem, not a calibration problem. Adjust bias before you re-run calibration.

Response curve

Per-axis curve shaping.

Most modern sims let you set curves in-game, so you often do not need this. It exists for the ones that do not — and for defining curves that a button can toggle at runtime.

The EQ flag

Each curve has an EQ checkbox. Ticked means “apply this curve to this axis always”. Unticked means the curve is dormant, and can instead be switched on dynamically — for example by a button.

Easy to miss

If you edit a curve and nothing happens, you almost certainly forgot to tick EQ.

Logical axes

The table that maps physical axes onto what Windows reports. Each logical axis has a Source — the physical axis feeding it.

Worked example from the video: to make logical axis 1 be your X axis, find which physical axis X actually is (on a default stick, physical axis 1) and set logical axis 1's source to it.

Advice

“I'd recommend honestly leaving all these settings at defaults… you can come here and invert it if you want to, definitely keep these on visible and enabled.”

Axes → Buttons

Turns axis travel into button presses. Define zones — ranges of axis movement — and each zone fires a different virtual button when the axis enters it.

The video's example sets up Edges 2, so pulling the stick to either extreme activates a different button. This is how you get “pull fully back = boost” style bindings.

Double-click the button cell to pick which virtual button the zone triggers.

Buttons

Split into two layers, mirroring the axis model:

Physical layer — what the switch does

For each physical button you choose its function type:

TypeMeaning
ButtonOrdinary press. The default.
Button alternateSecond action while held.
ShiftActs as a shift modifier for other buttons.
TemporaryActive only while held.
No functionDoes nothing. Useful for disabling a switch you cannot remove.

You set this by first pressing the button — in Test → Buttons/POVs — to see its physical number, then clicking the matching cell here.

Physical layer — which logical button it drives

Next to the function type you pick the logical button this physical button activates. Auto mapping means “same number”. You can change it to any logical button — the video remaps a trigger from logical button 10 to logical button 37, and later to a shift-aware pair using a virtual button.

Logical layer — what the logical button does

And finally, for each logical button, what Windows actually receives:

ActionEmits
Button pressAn ordinary button.
Hat switchA hat-switch direction.
KeyboardA keystroke — via the virtual keyboard from Global.
MouseA mouse button or movement.
MultimediaMedia keys (play, next track…).
SystemSystem actions.
MacroA macro sequence. See the Macro tab.
The whole model in two sentences

Physical layer: decide what the switch is and which logical button it fires. Logical layer: decide what that logical button does. You must do both, and they are on the same screen, which is why people lose track of which half they are editing.

POVs

Configuration for the hat switches.

  • Output type: hat switch, or numpad.
  • Resolution: 4-way, 6-way, 8-way.

Wiring a hat to an existing button

The video's example: the stick's hat right already activates logical button 28, so:

  1. In Buttons → Logical layer, find logical button 28.
  2. Set its action to Hat switch, and pick which hat (hat 1).
  3. Confirm in Test that the hat responds.

Per the POV tab, each POV can also be 4-, 6- or 8-way.

Boolean

Small logical rules: when this input is true, do that. The video's example — when physical button 12 is selected, activate virtual button 80, where virtual button 80 is already wired to light an LED.

This is how you build conditional behaviour without a full macro. More detail is in the manual.

#Macro tab

Records and plays back a sequence of inputs. Two things to set up.

1. Point a button at a macro

  1. Find the logical button you want to trigger it — e.g. logical button 80.
  2. In Buttons → Logical layer, set its action to Macro.
  3. Choose a macro number, e.g. macro 5.

2. Record what the macro does

  1. Go to the Macro tab, select the same macro number.
  2. Add entries — the video picks “mouse right button” and the keyboard A key.
  3. Click Set.
  4. Adjust its timing and repeat settings in the same panel.

Now pressing your stick button replays that whole sequence.

Two arrays

The current build exposes Macros Array 1 and Macros Array 2, so you can keep two independent macro banks and switch between them.

#Recipes

Change an LED's colour

  1. Select your device in the blue bar at the top.
  2. Global → LEDs.
  3. Pick an event — usually Event 0 for the idle state.
  4. Choose the LED, set the mode, then pick the colour.
  5. Press Set. Look at the physical stick — it has changed.

Find out which physical button a switch is

  1. Test → Buttons / POVs.
  2. Press the switch on your stick.
  3. Read the number that lights up. Write it down.

Remap a button

  1. Find its physical number (recipe above).
  2. Profile → Buttons → Physical layer. Click that row.
  3. Set the function type — usually leave as Button.
  4. Set which logical button it drives — leave as Auto unless you have a reason.
  5. Now in the Logical layer, find that logical button and set what it does.
  6. Press Set.

Make a switch act as Shift

  1. Profile → Buttons → Physical layer.
  2. Find the switch's physical number and set its type to Shift.
  3. Press Set.
  4. Now holding it should modify what your other buttons do. Verify on the physical stick.

Set up a throttle-shift layer

  1. Make your shifter a Shift physical button.
  2. In the physical layer, set your trigger to drive logical button 79.
  3. Assign logical button 80 to a virtual button — it has no physical switch of its own.
  4. In the logical layer, give buttons 79 and 80 different actions.
  5. Set. Trigger alone → 79. Trigger + shift → 80.

Fix a stick that has gone unresponsive

  1. Press Restart in the Action tab. This is the cheap fix.
  2. Still stuck? Replug the USB cable.
  3. Still stuck? Tools → Default resets everything to factory settings — this loses your configuration, so save it first if you have one.
  4. Still stuck? Tools → Bootloader and reflash the firmware.

Keep separate setups per game

  1. Configure for game A. Save → GameA.cfg.
  2. Configure for game B. Save → GameB.cfg.
  3. Before playing, Load the right file.
  4. Press Set — or turn on Settings → Set After Load and skip it.

#Gotchas

The things that reliably waste people's time.

You forgot Set

Nothing you change in the UI reaches the hardware until you press Set. This is by far the most common confusion.

Physical ≠ logical

You are editing a logical button; the switch you pressed is a physical button. They are different numberings connected by a table you must set deliberately.

Two layers on the Buttons screen

Set what the switch does on the physical layer and what the game receives on the logical layer. Both are required. Doing only one changes nothing.

Curve without EQ

Editing a response curve and seeing no effect almost always means EQ is unticked.

Not every LED is RGB

You cannot pick a colour for a fixed-colour LED. The software will let you try; nothing will change.

Only one device at a time

With a stick and a throttle both connected, configuration applies to whichever you selected in the blue bar. Re-select when you switch.

zconfig.ini is plain text

If an editor mangles it, you have lost your settings and the hidden UI. Keep a copy.

It crashes, sometimes

The video's author notes the software “sometimes randomly crashes for no reason”. That was true in 2022. Expect the occasional reset; keep your config files.

#What the video misses

VKBDevCfg is a ~23 MB C++Builder application whose binary embeds 69 form definitions — of which roughly 50 are VKB's own windows and dialogs and about 16 belong to the bundled FastReport library. Across them sit thousands of controls. The video openly says it covers only the basics. Decompiling the current build to map its UI surfaces a long tail of features the walkthrough never mentions.
